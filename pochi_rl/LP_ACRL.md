# 論文ベースの独立歩行ポリシー：LP-ACRL

[Scaling Rough Terrain Locomotion with Automatic Curriculum Reinforcement
Learning (arXiv:2601.17428)](https://arxiv.org/html/2601.17428v1) の課題選択手法を
Pochi / MuJoCo / mjlab に移植した、新しい PPO 歩行タスクです。
既存の Velocity、Deliberate Walk、StandUp、MPC の学習済み重みは使いません。
ロボットの CAD モデル・関節順序・RS02 モーターモデルのみ共有します。

初版は平地・不整地とも、別々のランダム初期値から1500回のPPO更新を完了しました。
初版不整地の独立評価は607/1200試行成功でしたが、停止姿勢と歩容の対称性に
問題がありました。以下の修正版は、それらを別の診断で検証します。

## 論文との対応

各課題について、完了したエピソードの報酬合計を集計します。
連続する評価期間の平均報酬の差を **符号付き** の learning progress として、
`p(task) = softmax(progress / beta)` で次の課題を選びます。
報酬そのものや改善量の絶対値による優先付けではありません。
課題はエピソード中固定で、リセット時に速度帯と地形を一緒に選びます。

実際のチェックポイントに保存された
[課題選択確率の推移](logs/rsl_rl/pochi_lp_acrl_rough/2026-10-06_scratch_guarded_explore_v2/curriculum_sampling_probabilities.png)
も出力しています。図は速度帯・旋回帯・地形ごとの選択確率を集計したもので、
成功率や地形の難易度を表すものではありません。

| 項目 | この実装 |
| --- | --- |
| 平地タスク | `Pochi-LP-ACRL-Flat-v0`：前後速度5区間、横移動・旋回は0 |
| 不整地タスク | `Pochi-LP-ACRL-Rough-v0`：速度5 × 旋回6 × 地形5 × 形状4 = 600課題 |
| 前後速度の絶対値 | 0〜0.5 m/s、0.1 m/s刻み。正負をランダムに選択 |
| 旋回速度の絶対値 | 0〜1.2 rad/s、0.2 rad/s刻み |
| 横速度 | 不整地は−0.1〜0.1 m/s、平地は0 |
| 地形 | 上り階段、下り階段、凹凸、上り坂、下り坂 |
| 地形の形状 | 段差2/4/6/8 cm、傾斜パラメータ0.075/0.15/0.225/0.3、凹凸幅1/2/3/4 cm |
| 行動 | 12関節の位置目標、`default_joint_pos + 0.25 * action` |
| 制御 | 50 Hz、物理計算は平地200 Hz・不整地400 Hz、Kp=140 / Kd=1.5、RS02トルク・速度特性 |
| 観測 | 平地48次元。不整地は地形の高さ275点を加える |
| 初期化 | ランダム重み、事前学習・模倣・固定の歩容位相なし |
| 学習器 | PPO、actor/critic は256→128→64、ELU、観測正規化 |
| 評価期間 | 20秒=1000ステップ |

論文は ANYmal D / Isaac Lab を使用しています。この実装は **Pochi 向けの移植** で、
論文の2.5 m/sや実機性能を再現したと主張するものではありません。
論文IV-Cの平地実験は0〜4 m/sを0.5 m/s刻みの8区間に分けています。
この実装の平地5区間（0〜0.5 m/s）はPochi向けの変更です。
不整地600課題の5×6×5×4という構成は論文の大規模実験に対応します。
不整地ポリシーはシミュレータの地形高さを観測する teacher です。
論文の実機用 LSTM student への蒸留と実機の地形推定は含みません。

論文に記載のない beta、課題分布の更新周期、PPO設定、ネットワーク構成、
データ不足時の扱いは実装側の選択です。標準設定は `beta=5`、
2400制御ステップ（PPO100更新）ごとに更新、各課題2エピソード以上です。
未観測・初観測・連続する期間に十分なサンプルがない課題の進捗は0とします。
最初の分布は一様で、手動の難易度順や重みのウォームスタートはありません。
途中再開用チェックポイントにはサンプラーの統計も保存します。

付録の観測表・高さグリッドは275点ですが、本文の108点という記述とは一致しません。
この実装は表に従います。また action-rate 式の差分欠落、四脚に対する足数の
添字の不整合は、目標関節位置の時間差分と四脚の接地イベントで解釈しています。
関節加速度ペナルティは Pochi の制御系に合わせ `-2.5e-7` にしています。
その他の報酬と地形の設定は保存される `params/env.yaml` を参照してください。

不整地の接触計算は CG ソルバーと楕円摩擦円錐を使います。Newton ソルバーでは
有限の低速状態から突然 NaN になる現象が発生し、保存した16状態を128環境で
再生すると摩擦円錐の種類によらず再現しました。同じ再生条件の CG では
200物理ステップがすべて有限でした。
[比較記録](logs/rsl_rl/pochi_lp_acrl_rough/2026-10-06_scratch_dt2p5/solver_replay_comparison.json)
と [MuJoCo Warp の関連報告](https://github.com/google-deepmind/mujoco_warp/issues/1415)
を残しています。再生では各環境の質量・摩擦の乱数値と直前のソルバー内部状態を
完全には復元していないため、数値エラーの詳細な原因まで証明したものではありません。
平地の物理設定は変更していません。

CGでも長時間学習中に有限の異常速度が一度発生し、その報酬が次期間のLPを
汚染した実験は停止しました。現在の不整地環境は、非有限の全身状態に加え、
関節速度200 rad/s、関節加速度1e6 rad/s²、胴体速度20 m/s、
胴体角速度50 rad/sを超える状態を検査します。これらは歩行の合否基準ではなく、
数値破綻を見つけるための広い上限です。
異常時は報酬計算・PPO更新・LP集計へ渡す前に学習を停止し、正常値を丸めたり、
異常を隠してリセットしながら学習を続けたりはしません。
`failure.json` / `failure.pt` に原因と生の状態を保存します。
`--enable-nan-guard` を付けると、最大32環境・直前16物理ステップの状態、
制御入力、ソルバーの初期値、質量・摩擦の乱数値も保存します。

完成した不整地の学習では、高さ地形との接触候補が内部上限50個に達する警告が
7回の収集区間で計3496行記録されました。超過した候補は接触計算から除外されるため、
有限値の検査だけでは検出できない物理計算上の制約です。警告行数は影響した環境数ではありません。
[発生区間と実装の調査記録](logs/rsl_rl/pochi_lp_acrl_rough/2026-10-06_scratch_guarded_explore_v2/heightfield_contact_overflow_audit.json)
を保存しています。全4候補の選択用評価と最終1200試行の独立評価では、この警告は
出ませんでした。ただし、採用モデルの学習には接触候補を打ち切った物理計算が含まれます。
評価が正常でも、学習時のこの制約が解消されたことにはなりません。

地形は24 m四方の20区画です。階段・坂は中心から外へ進むピラミッド型で、
中心の1.2 mはリセット用の平坦部です。低速でその場旋回する課題では平坦部を
出ないことがあります。地形生成シードは42で固定し、標準評価では学習と同じ
地形形状を使って速度指令・初期姿勢・物性を改めて抽選します。
最終独立評価は `--terrain-seed 123` で生成される凹凸の配置を変更しました。
階段・坂の形状、地形の種類・形状範囲は共通で、未知の形状範囲への評価ではありません。

## ゼロから学習

プロジェクトの既存 `.venv` を使います。追加の Python 環境は不要です。

```bash
cd /home/k_suzuki/fun_ws/Pochi/pochi_rl

# 不整地600課題。毎回新しい出力ディレクトリ、必ずランダム初期化。
.venv/bin/python scripts/train_lp_acrl.py \
  --task Pochi-LP-ACRL-Rough-v0 --gpu 1 \
  --num-envs 4096 --iterations 1500 --save-interval 100 \
  --linear-tracking-std 0.15 --yaw-tracking-std 0.5 \
  --initial-action-std 0.35 --minimum-action-std 0.12 \
  --fall-penalty -200 --enable-nan-guard

# 平地のみの独立した実験
.venv/bin/python scripts/train_lp_acrl.py \
  --task Pochi-LP-ACRL-Flat-v0 --gpu 1 \
  --num-envs 4096 --iterations 1500 \
  --linear-tracking-std 0.15 --yaw-tracking-std 0.2 \
  --initial-action-std 0.35 --fall-penalty -200
```

追従幅・探索量・転倒ペナルティの上書きは Pochi 向けの追加設定です。
速度範囲だけを縮めて追従カーネルの標準偏差0.5を維持した参照実験では、
1500更新後も正方向の指令に対し静止する解が残りました。許容幅だけを縮めた
実験では早い転倒に陥ったため、初期探索の振幅を小さくし、転倒時の報酬を追加しています。
`--fall-penalty -200` は制御刻み0.02秒が掛かり、転倒1回あたり−4です。
これらのオプションを省略すると参照設定（std=0.5/0.5、初期action std=1、
明示的な転倒ペナルティなし）になります。評価スクリプトはチェックポイントの
報酬設定を復元します。平地の学習済みモデルと実測結果は上記のとおりです。

不整地の上記コマンドは、旋回の追従幅を論文と同じ0.5に戻し、action stdに0.12の
下限を設けた実験です。探索量の下限は論文の指定ではありません。
旋回幅0.2・探索下限なしの不整地実験では、静止または前後に揺れる解が残りました。
複数の設定を同時に変えているため、改善を一つの設定だけの効果とは断定しません。

学習結果は `logs/rsl_rl/pochi_lp_acrl_rough/<日時>_scratch/` または
`pochi_lp_acrl_flat/` に保存されます。`run.json` にシード、初期化方法、
ソースとモデルのハッシュ、終了状態を記録し、ソースも保存します。
PPO設定と環境設定は `params/`、モデルは `model_<iteration>.pt` です。
反復番号は0始まりなので1500更新の最後は `model_1499.pt` です。

各実験は単一GPUで実行します。複数GPU間の課題統計の同期は未実装のため、
このタスクの runner は複数GPUでの起動を拒否します。
既存タスクの checkpoint は48次元などの入力サイズが一致しても読み込みを拒否します。
